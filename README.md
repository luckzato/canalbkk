# คลองกรุงเทพฯ — ระดับน้ำในคลองแบบเรียลไทม์

เว็บแสดงระดับน้ำจากสถานีตรวจวัด 311 จุดของสำนักการระบายน้ำ กทม. ออกแบบให้อ่านง่ายบนมือถือ มีแผนที่ ค้นหา กรองตามเขต/สถานะ หาสถานีใกล้ฉัน และสลับไทย/อังกฤษ

## โครงสร้าง

```
src/app.html        หน้าเว็บทั้งหมด (HTML + CSS + JS ไฟล์เดียว)
src/normalize.js    แปลงข้อมูลดิบของ กทม. ให้อ่านง่าย (ใช้ร่วมกันทั้ง Worker และ dev server)
src/worker.js       Cloudflare Worker: /api/stations ดึงข้อมูล + แคช 60 วิ + สำรองข้อมูลเก่าเมื่อต้นทางล่ม
scripts/build.mjs   สร้าง public/index.html และไฟล์พรีวิว
scripts/dev.mjs     เซิร์ฟเวอร์ Node สำหรับรันบนเครื่อง (ไม่ต้องใช้ Cloudflare)
data/snapshot.json  ข้อมูลจริงตัวอย่าง (8 ต.ค. 2569 03:05) ใช้ทำพรีวิว
preview/            พรีวิวแบบออฟไลน์ + ตัวอย่างผลลัพธ์ของ /api/stations
```

## รันบนเครื่อง

ต้องมี Node.js 18 ขึ้นไป

```bash
npm run dev          # เปิด http://localhost:8787
```

## Deploy ขึ้น Cloudflare (ฟรี)

```bash
npm install
npx wrangler login
npm run deploy       # ได้ URL เช่น https://canalbkk.<account>.workers.dev
```

ผูกโดเมนของตัวเองได้ที่ Cloudflare Dashboard → Workers → canalbkk → Settings → Domains & Routes

## Deploy ขึ้น Vercel (ฟรี)

โปรเจกต์มี `api/stations.js` (ทำหน้าที่เดียวกับ Worker) และ `vercel.json` พร้อมแล้ว

**ทางที่ 1: ผ่าน GitHub (ไม่ต้องติดตั้งอะไรบนเครื่อง)**
1. สร้าง repo ใหม่บน GitHub แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้
2. เข้า vercel.com → Add New → Project → Import repo นั้น
3. Framework Preset เลือก "Other" ที่เหลือใช้ค่าจาก `vercel.json` อัตโนมัติ → Deploy
4. ทุกครั้งที่ push ขึ้น GitHub เว็บจะอัปเดตเอง

**ทางที่ 2: ผ่าน Vercel CLI**
```bash
npx vercel login
npx vercel          # deploy ทดสอบ (preview URL)
npx vercel --prod   # deploy จริง
```

Vercel แคช `/api/stations` บน CDN 60 วินาที และใช้ข้อมูลเก่าได้ถึง 24 ชม. ถ้าต้นทางล่ม (`stale-if-error`) ฟังก์ชันรันที่สิงคโปร์ (`sin1`) ใกล้เซิร์ฟเวอร์ กทม.

## ทำไมต้องมี Worker

API ของ กทม. ไม่ส่ง header CORS เบราว์เซอร์จึงเรียกตรงจากหน้าเว็บอื่นไม่ได้ Worker ทำหน้าที่เป็นตัวกลาง:

1. เรียก `POST https://weather.bangkok.go.th/water/PageMap/GoogleMap` (body `payload=TEST_DATA_GOES_HERE`)
2. แปลงข้อมูลด้วย `normalize.js`
3. แคช 60 วินาที (ต้นทางอัปเดตทุก ~5 นาที) ช่วยลดภาระเซิร์ฟเวอร์ กทม.
4. ถ้าต้นทางล่ม ส่งข้อมูลล่าสุดที่เคยดึงได้ (ไม่เกิน 24 ชม.) พร้อม header `X-Cache: STALE`

## แท็บเรดาร์ฝน

- ภาพเรดาร์มาจาก RainViewer (`https://api.rainviewer.com/public/weather-maps.json`) เบราว์เซอร์เรียกตรงได้เลย ไม่ต้องผ่าน Worker
- แสดงย้อนหลัง 2 ชั่วโมง ทุก 10 นาที กดเล่นเป็นภาพเคลื่อนไหวได้ อัปเดตเองทุก 5 นาที
- ระบบอ่านสีจากภาพล่าสุด ณ ตำแหน่งสถานีวัดระดับน้ำ แล้วติดป้าย "ฝนตก" / "ฝนหนัก" ในรายการและหน้ารายละเอียดสถานี
- ข้อจำกัดของ API ฟรี (ตั้งแต่ 1 ม.ค. 2569): ภาพละเอียดสูงสุดที่ zoom 7 (ราว 1 กม./พิกเซล), ไม่มีพยากรณ์ล่วงหน้า, จำกัด 100 คำขอ/นาที/IP และใช้ได้เพื่อการส่วนตัวหรือการศึกษา ถ้าจะใช้เชิงพาณิชย์ต้องติดต่อ RainViewer
- เรดาร์ของ กทม. (หนองจอก/หนองแขม) ละเอียดกว่า แต่ภาพถูกป้องกันการนำไปแสดงที่เว็บอื่น หน้าเว็บจึงลิงก์ออกไปแทน
- เปิดหน้าเว็บด้วย `#radar` ท้าย URL เพื่อเข้าแท็บเรดาร์โดยตรง

## ข้อควรรู้

- เว็บ กทม. อยู่หลัง Cloudflare หากวันหนึ่งบล็อกคำขอจาก Worker ให้รัน `scripts/dev.mjs` บน VPS แทน (ตรรกะเดียวกัน) แล้วชี้หน้าเว็บด้วย `window.CANAL_API = 'https://your-server/api/stations'`
- API นี้ไม่มีเอกสารทางการ อาจเปลี่ยนได้โดยไม่แจ้ง ถ้าข้อมูลหาย ให้ตรวจที่ `normalize.js` ก่อน
- เกณฑ์ของสถานีเครือข่ายร่วมบางแห่งผิดหน่วย (เช่น 230/440) ระบบจะตัดค่าที่เกิน 10 ม. ทิ้ง
- เว็บนี้ไม่ใช่เว็บทางการของ กทม. ควรระบุแหล่งที่มาของข้อมูลไว้เสมอ (หน้าเว็บแสดงให้แล้ว)
- แผนที่ใช้ tile ของ OpenStreetMap (ไม่ต้องใช้ API key) เหมาะกับปริมาณผู้ใช้ทั่วไป ถ้าคนใช้เยอะมาก ควรเปลี่ยนไปใช้ผู้ให้บริการ tile แบบเสียเงินตามนโยบายของ OSM
